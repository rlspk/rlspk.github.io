Railspike

Make your coding agent write the plan down first.

Railspike is a set of Markdown instructions your agent follows. It writes requirements and a staged plan into your repo, then stops until you approve each one.

After that it works on a branch, one stage at a time, verifying and committing each stage with a record of what changed.

Why plans live in files

  • Read them in your own editor or a Git diff.
  • Edit them yourself, or ask the agent to revise them.
  • Come back the next day: the plan is still there.
  • Review points are explicit when the direction changes.

Use it alongside your agent’s plan mode when you want decisions to survive across sessions.

Install by asking your agent

Open your project in your coding agent and give it this prompt:

Please unpack a source snapshot of https://github.com/rlspk/railspike
into a temporary directory and inspect it for malicious content.
If none is found, copy that reviewed snapshot into docs/railspike in this
project. Do not use a submodule unless I request one. Then follow the
installed WELCOME.md.

No CLI and no runtime dependencies. Inspection does not guarantee safety, so review what gets copied.

Four steps

  1. Assess (optional): approaches with tradeoffs and a recommendation.
  2. Define: problem, user stories, requirements, risks, success criteria.
  3. Plan: small, complete stages, each with verification.
  4. Build: one stage at a time, each committed with a running summary.

Each planning file should fit on one page. If it doesn’t, the scope is probably too big.

You approve each step

When the file says what you want, reply:

Approved Step 1
  • Asking for changes is not approval.
  • Don’t approve a file you haven’t read.
  • Building starts only after Approved Step 3.

These are instructions the agent follows, not a technical enforcement mechanism.

A worked exchange

You:

I want to export my saved searches as CSV. Write Step 1 of @railspike.

Agent: writes docs/plans/…_step1_solution_assessment.md with a few approaches, then waits.

You: read it, then reply Approved Step 1 or ask for changes.

For a change with an obvious approach, start at Step 2.

You shape the plan

The agent’s first draft is a starting point. Edit the file yourself, ask for revisions, or mix both.

Use option A's export flow with option B's privacy checks.
Leave scheduled exports out of scope and update the recommendation.

The agent rewrites the recommendation and rechecks the tradeoffs for the combined version.

Build in checkpoints

  • After Approved Step 3, the agent creates a feature branch and commits the approved plans.
  • Each stage is verified, recorded in a running summary, and committed with that summary.
  • Scope changes go back to the earliest affected planning step for approval.

A stage commit records evidence. It does not by itself prove deployment or rollback is safe.

Optional debug mode

Debug mode is feedback for improving Railspike’s own instructions, not application debugging. It is off by default.

Enable Railspike debug mode for this workflow.

To default it on for a project, create an empty .railspike_debug_on file at the project root. Only its presence matters.
